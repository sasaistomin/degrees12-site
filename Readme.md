# DEGREES° 12 — магазин архивной одежды

Сайт на **Next.js 15** (React 19) + **Supabase** (база, вход, хранилище фото), хостинг **Vercel**.
Версия 2: серверный рендеринг для поиска Google, новый дизайн, три языка по отдельным адресам и расширенная админка.

---

## 1. Что умеет сайт

**Для покупателей**
- Главная, каталог, страницы категорий, страница каждого товара, «О нас».
- Три языка: `/ru`, `/uk`, `/en` (переключатель в шапке, язык по умолчанию берётся из браузера).
- Сортировка по цене, фильтр по категориям, пометка «Продано», кнопки «Заказать» (Telegram / Instagram).

**Для владельца (`/admin`)**
1. **Приветствие** — сводка: в наличии, продано, черновики, стоимость остатков.
2. **Доходы и посетители** — график выручки и прибыли (по месяцам или дням), график посетителей (7 / 30 / 90 дней), популярные страницы.
3. **Товары** — добавление, редактирование, загрузка фото, размеры, «Продано», скрыть, удалить, категории.
4. **Поиск товаров** — по ссылкам находит одежду в других магазинах (название, бренд, цена, фото, ссылка), считает вашу цену с наценкой (по умолчанию +10%), показывает число магазинов и возможную прибыль.

Вход в админку: логин `Istomin Sasha M`, пароль задан в Supabase (в коде не хранится).

## 2. Как сделан поиск в Google (SEO)

| Что | Где |
|---|---|
| Страницы отдаются готовым HTML (сервер), а не собираются скриптом в браузере | App Router, `app/(site)/[locale]/…` |
| У каждого товара и категории свой адрес, например `/ru/product/maison-margiela-caution-<id>` | `lib/utils.js` (`productSlug`) |
| Уникальные `title`, `description`, canonical, Open Graph, Twitter | `lib/seo.js`, `generateMetadata` на каждой странице |
| Версии на разных языках связаны (`hreflang`) | `lib/seo.js` → `alternates` |
| Карта сайта `/sitemap.xml` (все языки, категории, товары) | `app/sitemap.js` |
| `/robots.txt` (админка и API закрыты) | `app/robots.js` |
| Разметка schema.org: `Product` + `Offer` (цена, наличие), `BreadcrumbList`, `Organization`, `WebSite` | `components/JsonLd.jsx` |
| Страницы обновляются сами раз в минуту (ISR), а после правок в админке — сразу | `export const revalidate = 60`, `app/api/revalidate` |
| Админка закрыта от индексации (`noindex`) | `app/(admin)/admin/layout.jsx` |

> Новый сайт появится в Google не сразу. Добавьте его в **Google Search Console** и отправьте `https://ваш-сайт/sitemap.xml`: обычно первые страницы индексируются за несколько дней.

## 4. База данных (Supabase)

| Таблица | Поля |
|---|---|
| `categories` | name, color, text_color, position |
| `products` | name, **brand**, category, sizes[], price, **cost** (себестоимость), photo, **description**, sold, **sold_at**, hidden, **source_url**, **source_store**, created_at |
| `page_views` | path, locale, visitor_id, created_at (анонимный счётчик посещений) |

Жирным выделены новые поля. Хранилище фото — бакет `photos`.

**Права (RLS):** читать публичные данные может любой; менять товары, категории и фото, а также читать статистику может только администратор (`public.is_admin()`, проверка по почте). Посетители могут только добавлять строки в `page_views`.

**Как считаются деньги:** выручка = сумма `price` проданных товаров, прибыль = `price − cost` (если себестоимость указана). Дата продажи — `sold_at`, он ставится кнопкой «Продано».

**Посетители:** при открытии любой страницы сайт анонимно записывает адрес и случайный номер браузера (без cookie, без личных данных). Свои визиты админ не засчитываются.

## 5. Вкладка «Поиск товаров»: как это работает

1. Вставляете ссылки (товар, коллекция или главная магазина, до 5 за раз).
2. Сервер (`lib/extract.js`) пробует по очереди:
   - **Shopify** — публичные `/products.json` и `/products/<товар>.json` (название, бренд, цена, размеры, фото);
   - **JSON-LD** (`Product`, `ItemList`) — разметка, которую магазины дают для Google;
   - **Open Graph** — `og:title`, `og:image`, `product:price:amount`.
3. Цена продажи = `цена магазина × курс × (1 + наценка/100)`, округляется. Цену магазина, категорию и выбор можно поправить вручную.
4. «Добавить выбранные» создаёт **скрытые черновики** (`hidden = true`) со ссылкой на магазин. Проверьте их на вкладке «Товары» и нажмите «Опубликовать».

**Ограничения**
- Магазины, где товары подгружаются скриптом, закрыты от ботов или требуют вход, не читаются (будет сообщение «Ничего не найдено» или HTTP 403).
- Валюту магазин часто не указывает: поле «Курс к грн» задаёте вы.
- Автоматического поиска по всему интернету нет: вы указываете магазины сами. Это сознательно: так надёжнее и безопаснее.

**Фон у фото.** Нейросеть `@imgly/background-removal` работает прямо в браузере админа (подгружается с jsDelivr при первом использовании, ничего не платится). Фото из чужих магазинов сначала скачиваются через наш сервер (`/api/image`, только для админа, до 4 МБ), затем фон убирается, и результат (PNG) сохраняется в вашем хранилище Supabase. Это работает при добавлении из «Поиска товаров», при загрузке своих фото (галочка «Убирать фон у новых фото автоматически») и кнопкой ✂ у любого фото.

**Право и этика.** Фото, названия и описания в чужих магазинах защищены авторским правом, а правила многих сайтов запрещают автоматический сбор данных. Пользуйтесь функцией с магазинами-партнёрами и поставщиками, с которыми договорились (дропшиппинг, опт, кросс-продажи), и храните письменное разрешение на использование фото. Фото подтягиваются ссылкой (не копируются на ваш сервер), поэтому при смене картинки в магазине она изменится и у вас. Безопаснее загрузить собственное фото на вкладке «Товары».

## 6. Запуск и обновление

### Один раз
1. **Supabase → SQL Editor:** вставьте и выполните `supabase/migration.sql`. (Без него не работают себестоимость, графики и счётчик.)
2. **Vercel → проект → Settings → Build & Development Settings → Framework Preset → Next.js** (раньше стоял «Other»). Поля Build Command и Output Directory оставьте по умолчанию (не заполняйте).
3. В `lib/config.js` проверьте `SITE_URL` (ваш домен) и ссылки `CONTACT` (Telegram, Instagram).
4. (По желанию) Vercel → Settings → Environment Variables: `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Если не задавать, берутся значения из `lib/config.js`.
5. Отправьте код на GitHub (`git add . && git commit -m "v2" && git push`) — Vercel соберёт сайт сам.
6. Google Search Console: добавьте сайт и `sitemap.xml`.

### Проверка на своём компьютере (Node.js 18.18+)
```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # проверка сборки перед отправкой на GitHub
```

### Если что-то не работает
| Симптом | Причина и решение |
|---|---|
| Vercel: «Error: No Output Directory named "public"» или пустой сайт | Framework Preset не Next.js (шаг 2) |
| В админке «Не удалось получить статистику» | Не выполнен `migration.sql` |
| Вход: «Неверный логин или пароль» | В Supabase → Authentication → Users нет пользователя `istomin.sasha.m@degrees12.shop` с нужным паролем и Auto Confirm |
| Товар сохраняется с ошибкой про колонку | Не выполнен `migration.sql` |
| Изменения не видны на сайте | Подождите минуту (ISR) или обновите страницу с очисткой кэша |
| «Ничего не найдено» в поиске товаров | Магазин не отдаёт данные ботам. Попробуйте ссылку на конкретный товар |

## 7. Безопасность
- Ключ Supabase в коде публичный (publishable) — так и задумано: защищают правила базы (RLS), а не ключ. Секретные ключи (`secret`, `service_role`) в проект не вставляйте.
- Регистрация новых пользователей в Supabase должна быть **выключена** (Authentication → Sign In / Providers → Allow new users to sign up).
- API поиска и обновления проверяют токен входа и почту админа; поиск не ходит на внутренние адреса (защита от SSRF).
- Смена пароля: Supabase → Authentication → Users.
- Если репозиторий публичный, не добавляйте в него пароли и секретные ключи.

## 8. Что добавить, чтобы сайт стал уникальнее

**Бренд и контент**
1. **Истории вещей («archive notes»).** К каждой вещи короткий текст: из какой коллекции, год, чем редкая. Это и «лицо» магазина, и ключевые слова для Google. Поле `description` уже есть.
2. **Журнал / блог:** гайды «как отличить оригинал Rick Owens», «как стирать архивную кожу», обзоры коллекций. Лучший способ вырасти в поиске.
3. **Страницы брендов** (`/brand/rick-owens`) с историей бренда и всеми вашими вещами.
4. **Лукбуки и фото на людях:** вещь в образе и описание посадки («рост 180, размер M»).
5. **Видео-обзор** в карточке товара: 15 секунд, как сидит и как выглядит износ.

**Доверие**
6. **Паспорт вещи:** баллы состояния (1–10), фото дефектов, отметка «проверено вручную».
7. **Отзывы и счётчик проданного** («уже ушло 120 вещей») с реальными фото покупателей.
8. **Гарантия возврата и страница про доставку и оплату.**

**Фишки магазина**
9. **Вишлист и «следить за вещью»:** оповещение в Telegram, когда появится нужный бренд или размер.
10. **Подбор размера:** таблица замеров и калькулятор «по вашей любимой вещи».
11. **Telegram-бот или Instagram-витрина:** новые поступления автоматически в канал.
12. **Резерв вещи на 24 часа** и счётчик «смотрят сейчас».
13. **Дроп-календарь:** «в пятницу в 19:00 выходит новая подборка», подписка на уведомление.
14. **Подарочные сертификаты и промокоды** для первых покупателей.

**Технические**
15. **Корзина и онлайн-оплата** (LiqPay, Monobank Acquiring, Stripe): сейчас заказ идёт через мессенджеры.
16. **Несколько фото на товар** и увеличение по клику.
17. **Поиск по каталогу** и фильтры по размеру, бренду, цене.
18. **PWA** (иконка на экране телефона) и **быстрые графики** через SQL-функции для большой статистики.
19. **Подключить свой домен** (например, `degrees12.com.ua`): это повышает доверие и позиции в поиске.
20. **Google Analytics / Search Console** для связки «запрос в Google → вещь → продажа».
